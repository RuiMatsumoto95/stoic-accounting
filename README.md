# ストイック会計（Stoic Accounting）

仕訳を入力して、帳簿を見て、データを持ち帰る。それだけを素直にやるための、ブラウザで動く会計ソフトの試作です。

> [!WARNING]
> **これは実験段階のソフトです。次の3点を必ず守ってください。**
>
> 1. **実データを入れないでください。** 顧問先・自社・個人の会計データは対象外です。認証も、利用者ごとのアクセス制御も、まだありません。
> 2. **アプリを公開URLに置かないでください（公開ホスティング禁止）。** 公開URLに置くと、その URL を知る全員が、全データを読み、書き換え、削除できます（データベースの接続キーはブラウザに配られる設計です）。
> 3. **会計・税務の判断、申告、帳簿の法定保存には使えません。** 計算結果は無保証です。
>
> **データはクラウドにあります。** データベースは Supabase のクラウド上にあり、アプリを手元（localhost）で動かしても、データはそのクラウドに保存されます。認証とアクセス制御が未完成なので、接続キー（anon キー）を知る人は誰でも、そのデータベースを読み書きできます。接続キーを README・画面写真・公開リポジトリに載せないでください。

## 依存関係の脆弱性について（2026-11-19 時点）

`npm audit --omit=dev`（実行時に使われる依存）では、報告されている脆弱性は 0 件でした。開発時のみの依存では、`minimatch`（moderate）の脆弱性 1 件が残っており、上流の更新を待っています。GitHub の Dependabot alerts でも、Open は同じ 1 件です。

これは、依存パッケージの既知の脆弱性を確認した結果です。このアプリ自体の安全性（認証がないこと、アクセス制御がないこと）を示すものではありません。冒頭の警告（認証なし・実データ禁止）を必ず読んでください。

## これは何か

税理士である作者が、自分で使うために作っている複式簿記の会計ソフトです。キーボードだけで仕訳を切れること、帳簿がすぐ見られること、データを利用者の手元に置けることを優先しています。

- 状態: **実験段階（v0.1）**。作者1人が本業のかたわら保守しています。
- 対象: 法人と個人事業（1つの環境で複数の会社を切り替え）
- 構成: Next.js（App Router）＋ Supabase（PostgreSQL）

## 設計の考え方

- **仕訳入力は速く、単純に。** 日付は4桁（`1207` → 12/07）、科目はコードかローマ字、金額は `/` で `000`。日本語入力をオンにしたまま、マウスなしで1件を保存できます。
- **帳簿は仕訳から毎回つくる。** 残高を別に持たず、仕訳を唯一の元データにします。
- **整合性はデータベースで守る。** 借方と貸方の一致、会計期間、確定済みの年度への書き込み禁止は、画面ではなくデータベースの制約で止めます。
- **データは利用者のもの。** データベースは利用者自身の PostgreSQL です。標準的な形式で取り出せることを目標にしています（現状は「できること」を参照。まだ道半ばです）。
- **やらないことを決める。** 多機能な業務システムにはしません。

## できること

| 分類 | 内容 |
|---|---|
| 仕訳入力 | 仕訳日記帳（一覧上での入力・編集・複製、複合仕訳、検索、一括変更・一括削除）、伝票番号の自動採番 |
| 帳簿 | 総勘定元帳、補助元帳、残高試算表（貸借・損益）、補助残高一覧、消費税集計表 |
| 決算書 | 損益計算書、貸借対照表（法人用・個人用） |
| 年度 | 期首残高（前期からの自動繰越、手動設定）、年度の確定とロック |
| 会社 | 複数会社の切り替え、法人・個人の初期科目セット |
| 取り込み | CSV インポート（独自形式、弥生会計の仕訳データ形式。**単一仕訳のみ**。複合仕訳は警告を出して読み飛ばします） |
| 持ち出し | 仕訳日記帳の CSV エクスポート、各帳票の PDF 出力 |
| 履歴 | 仕訳の訂正・削除の記録（データベースに保存。**閲覧画面は未実装**） |

## まだできないこと

- **認証、利用者ごとのアクセス制御**（最優先の課題）
- 会社データの一括エクスポート、弥生形式でのエクスポート、決算書・試算表の CSV エクスポート
- 月次推移表、前期比較
- 決算整理仕訳の区別
- 申告書の作成、e-Tax 連携、銀行・クレジットカード連携
- 電子帳簿保存法の「優良な電子帳簿」の要件への対応
- インボイス制度の経過措置（80%控除など）の計算
- 証憑（領収書など）の保存
- スマートフォンでの入力（物理キーボードが前提です）
- 空のデータベースからの構築手順（下記「動かし方」を参照）

訂正・削除の記録は操作の記録であり、改ざんを防ぐ仕組みではありません。年度の確定も、認証がないため誰でも解除できます。


### 未整備: 画面を動かす

**現時点で、第三者が画面を動かすための手順は整っていません。** 理由は次のとおりです。

- `supabase/schema.sql` はテーブル・関数・制約の定義だけで、税区分マスタ（`tax_codes`）の初期データを含みません。
- 空の Supabase プロジェクトに `schema.sql` から環境を立てる手順は、まだ検証していません。

作者の環境では、次の構成で動かしています（Windows / Chrome）。

1. Supabase のプロジェクト（PostgreSQL 17）に `supabase/schema.sql` 相当のスキーマを適用する
2. `.env.example` を `.env.local` にコピーし、`NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` を入れる
3. `npm run dev` を実行し、`http://localhost:3000/journals` を開く

`npm run build` は `.env.local` がないと失敗します。構築手順の整備は今後の課題です。
