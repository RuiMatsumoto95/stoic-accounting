# アイデアのバックログ

旧資料に記録された候補を、現行実装との差分で記載する。「一部実装」は現行機能に追加する候補、「未実装」は該当する操作や機能がまだない候補、「構想」は必要性や対象範囲から検討する候補。「要検証」は現行実装の動作や数値を確認する候補。表の順番は採用順や日程を表さない。

## 仕訳入力と科目

| 候補 | 状態 | 検討する内容 |
| --- | --- | --- |
| 科目マスタへの入口 | 一部実装 | `/accounts` は直接開ける。共通ナビゲーションでの入口や、入力中に科目不足に気づいたときの導線を検討する。 |
| 補助科目の一括登録と検索キー | 一部実装 | 補助科目は個別に登録でき、科目には別名を持てる。補助科目の一括登録と、読み方・略称などの検索キーをまとめて設定する方法を検討する。 |
| 個別の補助科目の非表示 | 未実装 | 現在は表示設定で補助科目列をまとめて切り替える。使わなくなった補助科目を新規入力の候補から外し、過去の帳簿では参照できる扱いを検討する。 |
| 事務所内で使う標準マスタ | 未実装 | 会社作成には法人・個人別の初期科目セットがある。科目、検索用の別名、表示順、デフォルト税区分を事務所内の別会社でも再利用する単位を検討する。 |
| 仕訳検索結果の借方・貸方合計 | 未実装 | 日付や科目などの検索結果に合計を表示する。複合仕訳では、条件に合う明細と該当仕訳の全明細のどちらを集計するかを先に決める。 |
| 補助元帳から仕訳全体へ移動 | 未実装 | 補助科目の明細から、借方・貸方の全明細を一つの仕訳として確認できる入口を検討する。 |
| 仕訳テンプレートの再設計・複合仕訳への変換 | 一部実装 | テンプレートのDB定義と仕訳の複製操作がある。よく使う仕訳の呼び出し方と、入力済みの単純仕訳に明細を追加する操作の必要性を検討する。 |

現行仕様は [仕訳日記帳](../30-features/journals.md)、[勘定科目マスタ](../30-features/accounts.md)、[補助元帳](../30-features/subsidiary-ledger.md) を参照。

## CSV取込とデータの持ち出し

| 候補 | 状態 | 検討する内容 |
| --- | --- | --- |
| CSV形式の設定を保存 | 未実装 | 既存の独自・弥生形式に加え、列の割り当て、固定の科目・税区分・摘要、入出金の符号などを取込元ごとに保存し、登録前に確認できるようにする。 |
| ルールによる仕訳候補 | 未実装 | 現行のマッピングは、正規化した科目名の置換。取込時の照合で登録済みの優先度は使われない。候補作成では摘要・入出金方向・金額を条件に使い、完全一致・部分一致・優先度の意味、競合時の表示を検討する。銀行・カードの明細CSVを入力として使い、本登録は利用者が確認する。 |
| 既存CSVの取込精度 | 一部実装 | 確認画面で指定した補助科目の本登録、弥生形式の複合仕訳、同じファイルの再取込時の重複確認を検討する。税込・外税の扱いや、警告を行と列で確認できるかも範囲に含める。 |
| 取込元と確定仕訳の対応 | 構想 | 元CSVの行、表記の正規化で使ったルール、確定仕訳を関連付ける。元の摘要と確定時の表示を残す範囲、保存期間、再取込時の照合を検討する。 |
| 出力と再取込の互換性 | 一部実装 | 仕訳CSVは独自取込形式と列が異なり税区分を含まない。税区分を含めて再利用できる形式と、弥生形式・決算書・試算表のCSV出力を検討する。 |
| 会社データの一括持ち出し | 未実装 | 会社、科目、会計期、期首残高、仕訳などをまとめて出力する範囲を決める。人が閲覧するCSVと、移行・復元に使う形式に必要な項目を確認する。 |
| 追加の取引属性と外部証憑の参照 | 構想 | 取引先・品目・用途や証憑の外部参照IDを、必要な利用者だけが入力・検索・出力できるか検討する。必須項目、設定の単位、過年度の表示を確認する。 |
| AIによる仕訳候補 | 構想 | 列設定と再現可能なルールを先に検討する。AIを使う場合は、参照できるデータ、提案の根拠、利用者の確認、確定時の検証を設計する。 |

現行仕様は [CSVインポート](../30-features/csv-import.md) と [仕訳日記帳の出力](../30-features/journals.md#出力) を参照。

## 会計期と帳票

| 候補 | 状態 | 検討する内容 |
| --- | --- | --- |
| 帳票で参照する期の選択 | 一部実装 | 設定で当期を切り替えられ、期首残高画面は個別に期を選べる。記帳先の当期を保ったまま、帳票で過年度を確認する方法を検討する。 |
| 期首残高の入力補助 | 一部実装 | 自動導出・手動設定に加え、残高CSVや表の貼り付け、別会社の残高を手入力時に参照する方法を検討する。法人成りは別会社を作る方針に沿う。 |
| 月次推移・比較の拡張 | 一部実装 | 損益計算書・貸借対照表には前期比較がある。試算表への比較の展開、任意の期間同士の比較、月次推移表を検討する。 |
| 決算整理の前後を分けた試算表 | 未実装 | 決算整理仕訳を区別し、整理前・整理後の残高を再現できる集計条件を検討する。 |
| 決算書の区分・小計の見せ方 | 一部実装 | 法人・個人別の様式を土台に、売上原価の符号・小計、個人用貸借対照表の資本の内訳などを、画面とPDFで読み比べる。 |
| 部門別の集計 | 構想 | 部門を任意で指定できるようにし、帳票で部門を絞り込む案。共通費の配賦は対象外とする。 |

現行仕様は [期首残高](../30-features/opening-balances.md)、[損益計算書](../30-features/income-statement.md)、[貸借対照表](../30-features/balance-sheet.md)、[残高試算表](../30-features/trial-balance.md) を参照。

## 運用と検証

| 候補 | 状態 | 検討する内容 |
| --- | --- | --- |
| 仕訳の訂正・削除履歴の閲覧 | 一部実装 | DBに残る変更前の記録を、対象会社と権限を確認して閲覧する方法を検討する。操作者の記録と履歴の完全性は閲覧画面と併せて整理する。 |
| 認証と利用者ごとのアクセス制御 | 未実装 | 作業中の会社の選択に加え、利用者がどの会社や操作にアクセスできるかを、画面・帳票・DBを通じて検証する。 |
| 閲覧専用デモ | 構想 | 架空データで記帳結果や帳票を閲覧できる環境を検討する。公開前に、閲覧者に書き込みを許可しないことをDB側まで確認する。 |
| 初期構築と復元の検証 | 一部実装 | スキーマと変更SQLを使い、必要なマスタを含めた空のDBからの構築、バックアップの取得から復元までを検証する。 |
| 大量データ時の集計と出力 | 要検証 | 損益計算書・貸借対照表はページを分けて明細を取得する。元帳・試算表・仕訳一覧や出力にも、件数が増えたときに集計対象がそろうかを確認する。 |

現行の制約と公開順序は [ソース公開とデモの設計判断](../40-decisions/ADR-0015-source-before-hosted-demo.md)、[履歴の設計判断](../40-decisions/ADR-0012-journal-change-history.md)、[セキュリティの現状](../10-architecture/security.md)、[現在の構築条件](../../README.md#動かし方) を参照。
